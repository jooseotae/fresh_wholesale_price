- 문서 버전: v2.0

## 1. 배경

사용자는 대형마트 농산 담당으로, 이미 SAP 기반 일일 리포트 2종을 매일 운영 중이다. (바탕화면 파일에서 확인)

| 기존 리포트 | 지표 | 구조 |
|---|---|---|
| `농산_매출대시보드` | 총매출액 / 실매출액 / 매출총이익 / 매출총이익률, 전일·누계, YoY | 부문(채소 DBA / 청과 DCA / 양곡 DIA) → MC(자재그룹) 드릴다운 |
| `농산_손실율대시보드` | 손실율, 마크다운, 폐기로스, 재고차이, 매가변경, 기준매가위반 | 동일 구조 + MC 손실율 등락 TOP10 |

두 리포트 모두 **사내 실적(결과)** 만 본다. 즉 "왜 그렇게 됐는지"의 선행 변수인 **산지/도매 시세**가 빠져 있다. 배추 도매가가 3일째 급등 중이면 매가·발주·행사 판단을 미리 바꿔야 하는데, 현재는 매출·손실이 망가진 뒤에야 숫자로 보인다.

서울시농수산식품공사 유통정보시스템(garak.co.kr)이 그 선행 데이터를 매일 공개한다. 이를 **자동 수집 → 자사 MC 코드에 매핑 → 매일 아침 한 화면**으로 만드는 것이 이 프로젝트다.

## 2. 목표

**한 문장:** 매일 아침 출근 전, 내가 담당하는 농산 품목의 가락시장 시세 변동과 이상 신호를 자동 갱신된 한 화면으로 확인한다.

### 성공 기준

| # | 기준 | 측정 |
|---|---|---|
| G1 | 매일 정해진 시각에 사람 개입 없이 데이터가 갱신된다 | 7일 연속 수동 조작 0회 |
| G2 | 대시보드 확인에 3분 이내 소요 | 스크롤 없이 1화면에 핵심 요약 |
| G3 | 급등락 품목을 놓치지 않는다 | 임계치 초과 품목이 상단에 자동 노출 |
| G4 | 기존 매출/손실율 리포트와 품목 축이 맞는다 | 가락 품목 ↔ 자사 MC 코드 매핑 테이블 존재 |

### 비목표 (이번 범위 아님)

- 자사 SAP 매출/손실 데이터의 자동 수집 — 기존 Excel 리포트를 그대로 쓴다
- 발주량 자동 산출/자동 발주 연동
- 가격 예측 모델
- 수산·축산 부문 (농산 = 채소/청과/양곡만)

## 3. 사용자 및 사용 시나리오

**주 사용자:** 본인 1명 (농산 담당). 부가적으로 팀 공유 가능성 있음 → §9 Q4.

**시나리오 A — 아침 브리핑 (매일, 주 사용)**
> 08:00 출근. 대시보드를 연다. 상단 "오늘의 경보"에 `배추 +18%`, `오이 +9%` 표시. 배추 7일 추이 차트가 우상향. 전년 동일 시점 대비도 +40%. → 배추 매가 인상 검토, 대체 품목(양배추) 행사 전환 판단.

**시나리오 B — 손실율 이상 추적 (주 1~2회)**
> 손실율 대시보드에서 `020302 오이` 손실율이 악화. 가락 대시보드에서 오이 도매가가 급락 중임을 확인 → 판매 부진이 아니라 시세 하락에 따른 매가 조정 지연이 원인. 조치 방향이 달라진다.

**시나리오 C — 주간/월간 리뷰 (주 1회)**
> 담당 품목의 주간 평균가 vs 전년 동주 비교표를 확인, 다음 주 행사 품목 후보를 고른다.

### 4.1 소스 선정 방침

- **P0: D1 단독** — 인증 불필요, JSON, 검증 완료. 품목 12종 고정이라는 한계는 감수하고 먼저 돌린다. (결정 D-1)
- **P1: D2 + D3/D5 대체 경로** — 담당 품목 전체(사과/배/포도/토마토/파프리카/버섯류 등)로 확장하려면 필수. BIX5·OZ 우회 경로를 추가 조사해야 한다.
- **공식 OpenAPI(공공데이터포털/KAMIS)는 사용하지 않는다.** (결정 D-4) 따라서 사이트 개편에 따른 중단 리스크를 F13 실패 알림으로 흡수하는 것이 유일한 방어선이다.
- **D6(로그인 영역)** 은 산지별·법인별 분석까지 필요할 때만. 카카오 간편로그인 세션 자동화는 유지보수 리스크가 크므로 **후순위**.

## 6. 기술 설계 (안)

```
[Windows 작업 스케줄러]  매일 14:00
        │
        ▼
  collect.py ──▶ garak.co.kr JSON 엔드포인트
        │         (휴장일은 직전 거래일 값 반복 → 해시로 감지해 제외)
        │
        ▼
  data/prices.sqlite   (일자 × 품목 × 등급 시계열, upsert)
        │
        ▼
  build.py ──▶ dashboard.html  (자체 완결형: 데이터 인라인, 차트 인라인 SVG/JS)
        │
        ▼
  바탕화면 바로가기로 더블클릭 → 브라우저에서 즉시 열림
```

**선택 근거**
- **Python + SQLite**: 의존성 최소, 설치 부담 없음, 시계열 누적에 충분
- **정적 HTML 산출물**: 서버 상시 구동 불필요. 오프라인에서도 열림. 파일 하나만 관리
- **Windows 작업 스케줄러**: 별도 데몬 불필요, PC 부팅 후 놓친 실행도 보정 가능

**스키마 초안**
```sql
CREATE TABLE price_daily (
  trade_date TEXT,      -- YYYY-MM-DD (경락일)
  market     TEXT,      -- garak | gangseo
  item_cd    TEXT,      -- 가락 품목코드
  item_nm    TEXT,
  unit_nm    TEXT,      -- 10키로망대 등
  grade_nm   TEXT,      -- 특/상/보통/하
  low_price  INTEGER,
  avg_price  INTEGER,
  max_price  INTEGER,
  price_gap  INTEGER,   -- 전일대비 원
  volume     INTEGER,   -- 반입물량 (확보 시)
  collected_at TEXT,
  PRIMARY KEY (trade_date, market, item_cd, grade_nm)
);

CREATE TABLE item_map (   -- 가락 품목 ↔ 자사 MC
  item_cd TEXT PRIMARY KEY,
  mc_cd   TEXT,          -- 020101
  mc_nm   TEXT,          -- 배추
  buy_grp TEXT,          -- DBA/DCA/DIA
  watch   INTEGER        -- 1이면 대시보드 노출
);
```

**리포지토리 구조**
```
fresh_wholesale_price/
├─ docs/PRD.md
├─ src/collect.py        # 수집
├─ src/build.py          # 대시보드 생성
├─ config/items.json     # 담당 품목 + MC 매핑 + 경보 임계치
├─ data/prices.sqlite
├─ out/dashboard.html
└─ logs/
```

## 7. 단계 계획

## 8. 제약 및 전제

- 실행 환경: Windows 10, 로컬 PC (`C:\workspace\fresh_wholesale_price`)
- PC가 꺼져 있으면 해당 일자 수집 불가 → 다음 실행 시 누락분 백필로 보정
- **가락 데이터는 내부 참고용**. 사이트 고지대로 계약·납품·손해배상 증빙에 사용 불가
- 자사 SAP 데이터는 이번 범위에서 자동 연동하지 않음
- 현재 Claude in Chrome 확장이 연결되어 있지 않아, **로그인된 브라우저 창을 직접 제어할 수 없다**. D6(로그인 영역) 조사는 확장 연결 또는 사용자가 직접 확인해 주는 방식이 필요하다.

## 9. 확정 사항

| ID | 결정 | 근거 / 영향 |
|---|---|---|
| **D-1** | P0 품목 범위 = **D1의 12품목** | 검증된 무인증 JSON으로 즉시 착수. 채소(DBA) 주력 품목은 대부분 커버. 실사용 후 P1 확장 범위 재조정 |
| **D-1a** | 품목 목록은 **DB 자동 탐지**로 결정한다. `config/items.json`은 허용목록이 아니라 MC 매핑 레이어 | 공사가 노출 품목을 바꿔도 대시보드가 자동으로 따라간다. 미매핑 품목은 배너로 알림 |
| **D-2** | 산출물 = **정적 HTML + 바탕화면 바로가기** | 서버 상시 구동 불필요, 파일 하나만 관리, 오프라인에서도 열림 |
| **D-3** | 갱신 = **매일 14:00, 당일치 우선** | 과일류 확정(11시) 이후 시각. 아래 D-3a 폴백 규칙 적용 |
| **D-3a** | 휴장일은 **페이로드 해시로 감지**해 집계에서 제외하고, 대시보드에 기준 거래일을 명시한다 | 구현 중 실측으로 규칙이 바뀌었다. API는 휴장일에 빈 응답이 아니라 **직전 거래일 값을 그대로 반복 반환**한다 (2026-08-22와 08-23 페이로드 해시 일치). 따라서 "빈 응답 폴백"이 아니라 해시 비교로 `is_carry=1` 을 표시하는 방식을 쓴다 |

### 조사로 뒤집힌 가정

**"주요품목 12종이 계절에 따라 교체될 것"** — 사실이 아니다. 2025-07 ~ 2026-08 13개월치를

비출하기에 결측이 생길 뿐, 신규 품목은 등장하지 않는다.

P1의 소스 확장이 반드시 필요하다.** 대신 D-1a(자동 탐지)로 공사가 품목을 바꿀 경우에는
