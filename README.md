# 가락시장 도매시세 대시보드

서울시농수산식품공사 유통정보시스템에서 농산 도매시세를 매일 자동으로 받아
정적 HTML 대시보드로 만든다. 사내 SAP 리포트(매출·손실율)가 **결과**만 보여주는 데 반해,
이건 그 결과를 만드는 **선행 지표**(도매 경락가·반입량)를 본다.

설계 배경은 [docs/PRD.md](docs/PRD.md), API 호출 규약은 [docs/SOURCES.md](docs/SOURCES.md) 참고.

## 쓰는 법

Vercel에 배포돼 있다. 배포 주소는 Vercel 프로젝트 페이지에서 확인한다.
로컬에서 보려면 저장소 루트의 `index.html` 을 그대로 열어도 똑같이 동작한다 (서버 불필요).

데이터는 작업 스케줄러가 하루 세 번 갱신한다.

| 시각 | 작업 | 범위 | 이유 |
|---|---|---|---|
| 08:00 | `가락시세_채소` | 채소만 | 채소 경매는 새벽에 끝난다 |
| 11:00 | `가락시세_청과` | 청과만 | 청과는 오전 중 확정된다 |
| 14:00 | `가락시세_마감` | 전체 + 뉴스 | 최종 확정값으로 전체 재확인 |

부문을 나눈 이유는 **갱신 시각을 정직하게 보여주기 위해서**다. 08시에 채소만 들어왔는데
청과까지 "방금 갱신"으로 표시하면 오해를 부른다. 그래서 값이 실제로 바뀔 때만
`collected_at` 을 올리고, 상단 노란 배지에 부문별 갱신 시각을 따로 적는다.

`가락시세_마감` 에만 **놓친 실행 따라잡기**(StartWhenAvailable)를 켜뒀다. 세 작업 모두
켜면 PC를 하루 꺼놨다 켤 때 셋이 동시에 실행돼 SQLite 쓰기와 git 인덱스가 충돌한다.
마감 한 번이면 어차피 전 부문을 다 채우므로 이걸로 충분하다.

> **PC가 켜져 있어야 한다.** 수집은 이 컴퓨터에서 돌고 Vercel은 결과물만 서빙한다.

## 대시보드 사용법

**드릴다운 3단계** — 전체 → 채소/청과 → 품목별 품종

- 상단 탭(`전체` `채소` `청과`)으로 어느 단계에서든 자유롭게 이동한다
- 품목 행이나 카드를 클릭하면 다음 단계로 (붉은 안내 문구 + 행 오른쪽 `›`)
- 오른쪽 위 큰 **← 돌아가기** 버튼, 또는 **브라우저 뒤로가기 / 백스페이스**
- 2단계는 품목 검색(**부문 무관 전체 검색**), 3단계는 품종·규격 조합 검색 (`천도 10kg`)
- 3단계에는 등급 필터 칩(특/상/보통/하)이 붙는다

주소가 `#채소/양파` 형태로 바뀌므로 **그 주소를 공유하면 상대도 같은 화면**을 본다.

담고 있는 것: KPI 카드, 전일대비 등락 막대, 급등락 다이버징 바, 부문별 반입량 TOP10,
계절 TOP1 주간 누적, 품목 소개 카드(주요 품종·산지·가격대), 가격·반입량 추이 선그래프,
품종별 규격 표, 산지별 시세, 하단 농산물 뉴스(D-5).

디자인은 [shadcn/ui](https://ui.shadcn.com) 디자인 시스템을 순수 CSS로 이식했다.
토큰·라운드·그림자·컴포넌트 스타일만 가져왔고 React·Tailwind 의존성은 없다.
자세한 내용은 [docs/worklog/2026-09-02.md](docs/worklog/2026-09-02.md).

## 구조

```
src/collect_bix5.py  대표품목 가격(품종·등급) + 부류별 반입량   ← 주력
src/collect_unit.py  규격별 가격 + 산지별 가격                  ← 조합마다 개별 요청, 약 150초
src/collect_news.py  게시판 뉴스 (동향·전망 / 유통자료실)
src/collect.py       12품목 (P0 소스, 1년치 이력 유지용)
src/build_v2.py      SQLite -> index.html + out/dashboard.html
src/template.html    대시보드 템플릿 (화면 수정은 전부 여기서)
config/items.json    가락 품목코드 ↔ 자사 MC 매핑
run_daily.cmd        스케줄러 진입점 (인자 없음=전체, 채소, 청과)
vercel.json          캐시 헤더만 (라우팅 설정 없음)
docs/SOURCES.md      API 호출 규약 — 건드리기 전에 반드시 읽을 것
docs/worklog/        날짜별 작업 일지
docs/ppt/            경영진 보고 PPT + 생성 스크립트
```

의존성은 없다. Python 표준 라이브러리만 쓴다.
(`package.json` 의 pptxgenjs는 PPT 생성 스크립트 전용이라 수집·빌드와 무관하다.)

## 알아둘 것

**품목은 고정이 아니다.** 초기에 12종 고정으로 판단했으나 BIX5 소스를 뚫으면서 풀렸다.
지금은 공사가 노출하는 대표품목 전체(81종)를 따라간다. `config/items.json` 은
허용목록이 아니라 **매핑 레이어**라서, 모르는 품목이 나타나면 `MC 미매핑` 으로 표시하고
상단 배너로 알린다. 그때 매핑만 추가하면 된다.

**청과/채소 경계는 자사 기준으로 다시 나눈다.** 가락시장 `과일과채류` 부류에는
토마토·참외·수박·멜론과 오이·호박·가지가 같이 들어있는데, 자사 MC 기준으로는 앞쪽이
청과(DCA), 뒤쪽이 채소(DBA)다. 그래서 `오이·호박·애호박·쥬키니호박·가지` 는 채소로
강제 분류한다 (`build_v2.py:FRUITVEG_TO_VEG`).

**휴장일 처리** — API는 휴장일에 직전 거래일 값을 그대로 되돌려준다. 페이로드 해시가
직전일과 같으면 `is_carry=1` 로 표시하고 집계·차트에서 제외한다. 현재 406일 중 69일이
휴장일로 잡혀 있다.

**품종 교체 구간의 급등락** — 햇사과가 나오기 시작하면 전일대비가 수백 %로 찍힌다.
데이터 오류가 아니라 실제 경락가 변화지만, 같은 품목의 연속 시세로 읽으면 안 된다.

**수입 품목의 산지** — 바나나·오렌지 등은 산지가 `기타` 하나로만 잡힌다. 원본이 국내
시군구만 구분하기 때문이라 버그가 아니다. 대시보드는 이 경우 표 대신 설명 문구를 보여준다.

**`run_daily.cmd` 는 ASCII만 쓴다.** cmd.exe가 OEM 코드페이지로 바이트 단위 파싱하는데
파일 안의 `chcp 65001` 이 파싱 도중 코드페이지를 바꾼다. 한글 바이트가 하나라도 있으면
정렬이 깨져 주석 조각이 명령으로 실행된다. 부문 인자(`채소`/`청과`)는 작업 스케줄러가
넘기는 값이라 파일에 적지 않는다.

**이용 제한** — 사이트 고지에 따라 이 자료는 내부 참고용이며, 계약·납품·사실조회 등의
근거·증빙자료로 사용할 수 없다.

## 배포 (Vercel)

`build_v2.py` 가 저장소 루트에 `index.html` 을 쓰고, Vercel이 그걸 `/` 에 그대로 서빙한다.
`vercel.json` 에는 캐시 헤더만 있다 — `cleanUrls` 나 `rewrites` 를 쓰면 404가 난다
(정적 파일 서빙과 충돌).

배포 흐름:

1. 수집 → 2. `index.html` 재생성 → 3. 데이터가 바뀌었으면 자동 커밋·푸시 → 4. Vercel 자동 재배포

`run_daily.cmd` 는 `git diff --quiet` 로 변경 여부를 먼저 확인해서, 값이 그대로면
커밋하지 않고 넘어간다.

**인증** — GitHub PAT가 `.git/config` 의 remote URL에 들어있다. 이 파일은 커밋되지 않으므로
저장소에는 노출되지 않는다. 토큰 만료 시 `setup_git_push.cmd` 로 다시 설정한다.
